# Content Management System

This directory contains all content for TC Heiner's portfolio website, organized into type-safe collections with automatic validation.

## 📁 Content Collections

### Posts (`/posts/`)
**Blog posts and articles**
- **Naming**: `post-YYYY-MM-DD.mdx`
- **Schema**: `title`, `startDate`, `description?`, `image?`, `tags?`, `canonical?`
- **Indexed by AI**: ✅ (Full content searchable by chatbot)

### Projects (`/projects/`)  
**Portfolio project showcases**
- **Naming**: `project-YYYY-MM-DD.mdx` or descriptive names
- **Schema**: `title`, `startDate`, `description`, `image?`, `tags?`
- **Indexed by AI**: ✅ (Technical details and accomplishments)

### Experiences (`/experiences/`)
**Professional work experience**
- **Naming**: `experience-YYYY-MM-DD.mdx` or company names
- **Schema**: `title`, `company`, `startDate`, `endDate?`, `tags?`
- **Indexed by AI**: ✅ (Skills, responsibilities, achievements)
- **Current positions**: Omit `endDate` field

### Books (`/books/`)
**Book reviews and reading notes**
- **Naming**: `book-YYYY-MM-DD.mdx` or book titles
- **Schema**: `title`, `author`, `readYear`, `tags?`
- **Indexed by AI**: ❌ (Personal reading, not professional content)

### Recipes (`/recipes/`)
**Cooking recipes and culinary experiments**  
- **Naming**: `recipe-YYYY-MM-DD.mdx` or dish names
- **Schema**: Complex recipe schema (see template)
- **Indexed by AI**: ❌ (Personal content, not professional)

### Algomonster (`/algomonster/`)  
**Algorithms Review**
- **Naming**: `xx.mdx` or descriptive names
- **Schema**: `title`, `startDate`, `description`, `image?`, `tags?`
- **Indexed by AI**: ✅ (Algorithm review)

## 🛠️ Content Creation Workflow

### Quick Start
```bash
# Create new content with templates (recommended)
./templates/create-content.sh post        # → post-2025-09-02.mdx
./templates/create-content.sh experience  # → experience-2025-09-02.mdx
./templates/create-content.sh project     # → project-2025-09-02.mdx

# Validate all content
node validate-mdx.js

# Update AI chatbot knowledge (if content is indexed)
cd backend && python -c "from chatbot.services import rebuild_vectorstore; rebuild_vectorstore()"
```

### Manual Creation
1\. Copy appropriate template from `/templates/`
2\. Rename with proper naming convention
3\. Fill in frontmatter and content
4\. Validate with `node validate-mdx.js`

### Content Guidelines

#### Frontmatter Requirements
- **All dates**: Use `YYYY-MM-DD` format
- **Tags**: Array of strings `["tag1", "tag2"]`
- **Images**: Relative paths from `/public/` directory
- **Optional fields**: Include `?` in schema, can be omitted

#### Content Best Practices
- **Professional content** (posts, projects, experiences) should be detailed for AI indexing
- **Use descriptive titles** and tags for better discoverability
- **Include images** when available for visual appeal
- **Link to related content** using relative paths

## 🔍 Schema Validation

### Validation Process
```bash
node validate-mdx.js  # Validates ALL MDX files
# Fix any reported errors before committing
```

### Common Schema Errors
```yaml
# ❌ Wrong date format
startDate: 2025/09/02      # Wrong
startDate: 2025-09-02      # Correct

# ❌ Invalid tags format  
tags: "tag1,tag2"          # Wrong - string
tags: ["tag1", "tag2"]     # Correct - array

# ❌ Missing required fields
# title: "Missing title"   # Wrong - commented out
title: "My Project"        # Correct

# ❌ Current position with end date
endDate: null              # Wrong - use null or omit
# endDate:                 # Correct - commented out or omitted
```

## 🤖 AI Chatbot Integration

### What Gets Indexed
The AI chatbot automatically indexes content for intelligent Q&A:

**Indexed Collections** (searchable by users):
- ✅ **Posts**: Full blog post content, code examples, insights
- ✅ **Projects**: Technical details, challenges, solutions, tech stack
- ✅ **Experiences**: Job responsibilities, achievements, skills used

**Not Indexed** (personal content):
- ❌ **Books**: Reading notes and personal reflections
- ❌ **Recipes**: Cooking content not relevant for professional queries

### Content Update Impact
When you modify indexed content (posts/projects/experiences):

1. **FAISS index rebuild required** for AI to see changes
2. **Container redeployment needed** for AWS Lambda updates
3. **Responses improve** with fresh, accurate information

```bash
# After editing indexed content:
cd backend
python -c "from chatbot.services import rebuild_vectorstore; rebuild_vectorstore()"
./build-container.sh  # Deploy to AWS
```

## 🛤️ Adding New Routes/Collections

To add a new content collection and route:

### 1. Define Collection Schema
Add to `/src/content/config.ts`:
```javascript
const newCollection = defineCollection({
  type: "content",
  schema: z.object({
    title: z.string(),
    startDate: z.date(),
    description: z.string(),
    // Add other required fields...
    tags: z.array(z.string()).optional(),
  }),
});

// Export in collections object
export const collections = {
  // ... existing collections
  newcollection: newCollection,
};
```

### 2. Create Content Directory
```bash
mkdir src/content/newcollection/
```

### 3. Create Page Routes
```bash
mkdir src/pages/newcollection/
```

Create `/src/pages/newcollection/index.astro`:
```astro
---
import { getCollection } from "astro:content";
import IndexPageLayout from "../../layouts/IndexPageLayout.astro";

const items = await getCollection('newcollection');
items.sort((a, b) => new Date(b.data.startDate) - new Date(a.data.startDate));
---

<IndexPageLayout title="New Collection">
  &lt;!-- Display logic here -->
</IndexPageLayout>
```

Create `/src/pages/newcollection/[...slug].astro` for individual pages:
```astro
---
import { getCollection } from "astro:content";
import MDXLayout from "../../layouts/MDXLayout.astro";

export async function getStaticPaths() {
  const items = await getCollection('newcollection');
  return items.map((item) => ({
    params: { slug: item.slug },
    props: { item },
  }));
}

const { item } = Astro.props;
const { Content } = await item.render();
---

<MDXLayout frontmatter={item.data}>
  <Content />
</MDXLayout>
```

### 4. Validate Setup
```bash
node validate-mdx.js  # Check schema compliance
npm run dev          # Test routes work
```
